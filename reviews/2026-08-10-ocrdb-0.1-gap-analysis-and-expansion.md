# OCRDb 0.1 — Gap Analysis & Expansion Recommendations

**Date:** 2026-08-10
**Status:** External review addendum to `RATIFICATION.md` — feeds the ratification session as additional big rocks + fill work. Nothing here is ratified.
**Method:** Full read of ocrdb-draft-0.1 (5 domains, 320 entries, verified against the RATIFICATION.md inventory), cross-checked against panopticon's 4.x history (DEVELOPMENT.md incidents, run-3 findings, baskin dogfood) and standard prior art (CWE, ASVS, CERT, OWASP LLM Top 10, ISO 5055, WCAG).
**Provenance discipline:** every recommendation below is tagged **[corpus]** (observed in panopticon's own history), **[prior-art]** (crosswalk-seeded), or **[invented]** (invention budget, justify per charter). Proposed codes are **provisional** — letter assignment is free until the pre-tag re-letter pass.

## Part 1 — Structural rulings needed BEFORE filling (P0)

### R1. Single-homing rule + duplicate-cluster inventory

The draft contains cross-domain duplicate entries. Under 5.0's code-as-identity design, every duplicated home guarantees reconcile splits: the code panel assigns the COD code, the security panel assigns the SEC code, and one finding becomes "one resolved + one new" across runs — the exact #914 churn the identity spine exists to kill. This will also directly degrade the Gate A assignment-stability eval (see `2026-08-10-5x-roadmap-combined-review.md`).

**Verified duplicate clusters (full inventory from the draft):**

| Cluster | Entries | Note |
|---|---|---|
| SQL injection | `COD-E1D` = `SEC-A3A` | Identical name, both CRITICAL |
| Untrusted-build code execution | `COD-E1E` = `SEC-E3C` | Near-identical |
| XXE | `COD-E1A` ≈ `SEC-A4B` | |
| Unescaped output | `COD-E1B` ≈ `SEC-B1E` | |
| Symlink following | `COD-E1C` ≈ `SEC-D1C` | |
| Thread-unsafe shared state | `COD-E2A` = `ARC-E2A` ≈ `SEC-F2B` | THREE homes |
| Unclosed handle / resource leak | `COD-A1B` ≈ `SEC-F2A` ≈ `TST-D1C` | THREE homes |
| Fail-open controls | `ARC-F2B/F2C` ≈ `SEC-G2A/G2B` | Already big-rock-flagged |
| Test architecture | `ARC-H` ≈ `TST-C/…` | Already big-rock-flagged, pair map exists |

**Proposed rule (charter/SCHEMA text):** *Each hazard single-homes in exactly one domain. Other domains may cross-reference (`see_also:`) but never re-enter the hazard.* Suggested resolutions: exploitable-by-an-adversary classes single-home in **SEC** (COD-E1 dissolves into cross-refs); concurrency hazards single-home in the new **COD-G** (below), absorbing all three thread-safety entries; resource leaks single-home in COD (SEC-F2A becomes a cross-ref). Open sub-ruling: does `TST-D1C` survive as "leak *in test code*" (a different finding than a product-code leak) or fold in? Recommend it survives — the remediation owner and severity profile differ.

### R2. Severity-calibration pass on typical_severity anchors

Anchors become load-bearing in 5.0: they drive the override discipline (every deviation costs a disclosed override + advisor adjudication), so an inflated anchor generates permanent override noise. Flagged as inflated on direct read: `ARC-D3C missing-referenced-file` (CRITICAL → HIGH at most), `ARC-E1C hardcoded-absolute-path-in-source` (CRITICAL → MEDIUM/HIGH). Proposed CRITICAL bar for the pass: *exploitable now, data loss, or silently wrong results at scale.* Walk every CRITICAL/HIGH anchor against it during ratification (there are few; this is an hour, not a week).

### R3. `automated_by` enrichment field (schema addition; direct token payoff)

Add an optional per-entry field mapping the issue to the linter/formatter rule that catches it mechanically:

```yaml
automated_by: [ruff:E401]     # list; empty/absent = requires judgment
```

Candidate entries already in the draft: `QAL-B1A combined-imports-single-line` (ruff:E401, n=20 — twenty LLM-reported instances of a free lint), `QAL-B1B redundant-shadowing-import` (ruff:F811), `QAL-B1C mid-file-import` (ruff:E402), `QAL-B2B line-too-long` (ruff:E501), `QAL-F3C noqa-annotation-usage`, `TST-C5B nonstandard-import-placement`, portions of `QAL-B2`/`B3`.

**Consumer behavior (panopticon 5.0):** when the tool scan ran, panel prompts instruct reviewers to SKIP `automated_by` issues; the report discloses the suppression class. Effect: stop paying reviewer-model prices for machine-catchable findings, and the taxonomy itself encodes why they're absent. This is the DB-side twin of the Track-2 verify economics.

### R4. Grammar capacity check (no action)

26 areas/domain, 9 categories/area, 26 issues/category — all expansions below fit with generous headroom. No grammar change needed.

## Part 2 — Fill work in existing domains (P1, target 0.1)

### SEC — new area: web-session-and-browser-boundary **[prior-art: ASVS, OWASP Top 10]**

The largest credibility hole in the draft: no CSRF, session management, CORS, redirects, JWT, or ReDoS anywhere. A security taxonomy without CSRF fails an outside security reviewer's first sniff test — and the baskin dogfood already observed CSRF in the wild **[corpus]**. Provisional `SEC-I`:

- `1 session-management`: missing-secure-cookie-flags (MEDIUM), session-fixation (HIGH), missing-session-expiry (MEDIUM)
- `2 cross-site-request`: csrf-missing-token-protection (HIGH), open-redirect (MEDIUM), cors-misconfiguration (MEDIUM), missing-frame-protection-clickjacking (LOW)
- `3 token-and-federation`: jwt-algorithm-confusion (HIGH), jwt-missing-expiry-or-audience-validation (MEDIUM), oauth-redirect-uri-validation-gap (HIGH)
- `4 adversarial-request-processing`: redos-catastrophic-backtracking (MEDIUM, CWE-1333), unbounded-request-size (MEDIUM). (Zip-slip stays in SEC-D path territory — cross-ref, don't duplicate; see R1.)

### SEC — new category: `B4 privacy-and-data-protection` **[prior-art]**

pii-in-logs (MEDIUM), excessive-data-collection (LOW), missing-retention-limit (LOW). Cheap now; promotes to a PRV domain only if demand shows. Keeps the CC-licensed taxonomy honest about covering privacy-adjacent review without founding a compliance framework.

### COD — new area: concurrency-and-asynchrony (provisional `COD-G`) **[prior-art: CWE-362 family, CERT CON rules]**

Single-homes the three orphaned thread-safety entries (R1). The corpus (single-threaded CLI) could never produce this area; competent review of any concurrent code demands it:

- shared-mutable-state-without-synchronization (MEDIUM — absorbs COD-E2A/ARC-E2A/SEC-F2B), check-then-act-race (MEDIUM — generalizes COD-A1A beyond files), atomicity-violation-compound-operation (MEDIUM), deadlock-lock-ordering (HIGH), blocking-call-in-async-context (MEDIUM), unawaited-async-result (MEDIUM), thread-unsafe-lazy-initialization (MEDIUM), unsafe-signal-handler (MEDIUM)

### COD — new area: data-representation-and-time (provisional `COD-H`) **[prior-art: CERT NUM/FLP, CWE-681/697]**

The most language-agnostic review catches in existence; the tree cannot express any of them:

- naive-aware-datetime-mixing (MEDIUM), dst-unsafe-time-arithmetic (MEDIUM), epoch-unit-confusion-ms-vs-s (MEDIUM), wall-clock-used-for-elapsed-time (LOW — monotonic-clock discipline), float-equality-comparison (LOW), precision-loss-in-numeric-conversion (MEDIUM), monetary-value-in-float (HIGH), integer-overflow-or-truncation (MEDIUM), bytes-string-conflation (MEDIUM), default-encoding-assumption (MEDIUM), unicode-normalization-mismatch (LOW), unit-confusion-in-quantity (MEDIUM)

### QAL — restructure area G (efficiency) from 4 invented entries into a real area set **[prior-art: ISO 5055 performance; invented, disclosed]**

- `G1 redundant-computation`: keep existing G1A/B/C
- `G2 algorithmic-complexity`: quadratic-scan-on-unbounded-input (MEDIUM), repeated-linear-search-in-loop (LOW)
- `G3 io-and-round-trips`: per-item-remote-call-chatty-io (MEDIUM — the generalized form; the DB-specific N+1 `QAL-G1D` **moves to DAT**, see Part 3), missing-pagination-or-streaming (MEDIUM), unbatched-bulk-operation (LOW)
- `G4 memory-and-allocation`: unbounded-cache-growth-no-eviction (MEDIUM), large-object-retention (LOW)

### TST — add the missing flakiness mechanisms + one forward-looking entry **[prior-art]**

Under TST-F: unseeded-randomness-dependent-test (MEDIUM), wall-clock-dependent-test (MEDIUM), test-order-coupling (MEDIUM — distinct from D1 state cleanup: passes alone, fails in suite, or vice versa). Under TST-A or B: universal-invariant-only-example-tested (LOW — the property-based-testing gap; future-proofs the domain).

## Part 3 — New domains

### DAT — data & persistence (P1: skeleton must exist at 0.1) **[prior-art seed]**

**Panopticon's `database` panel currently maps to NOTHING** — the 5.0 consumer mapping covers security/code/architecture/test; run 3 dispatched 2 database reviewers with no domain to code against. This is the inverse of every other gap: the consumer exists, the vocabulary doesn't. Provisional areas:

- `A schema-design`: missing-constraint-for-invariant (MEDIUM), nullable-column-ambiguous-semantics (LOW), missing-foreign-key-relationship (MEDIUM), inappropriate-type-for-domain (MEDIUM)
- `B migrations`: irreversible-migration-no-rollback (MEDIUM), destructive-migration-without-backfill (HIGH), table-lock-heavy-migration (HIGH), non-idempotent-migration (MEDIUM)
- `C query-patterns`: n-plus-one-query (MEDIUM — moved from QAL-G1D), missing-index-for-hot-query (MEDIUM), unbounded-result-set (MEDIUM), select-star-in-production-path (LOW)
- `D transactions-and-concurrency`: missing-transaction-boundary (HIGH), long-running-transaction (MEDIUM), isolation-level-mismatch (HIGH), read-modify-write-race (HIGH)
- `E data-lifecycle`: orphaned-rows-on-delete (MEDIUM), soft-delete-inconsistency (MEDIUM), code-schema-drift-without-migration (HIGH)

**Seeding synergy:** the corpus has near-zero DB surface. The external reference repo needed for the 4.3.x cost-ledger baselines should be a DB-heavy project — the same run produces DAT corpus. One run, two deliverables.

### AGT — agentic/LLM trust (P1: rules big rock #1 as "promote") **[corpus + prior-art: OWASP LLM Top 10]**

Recommendation on RATIFICATION big rock #1: **promote SEC-G to a domain.** It's the project's differentiator territory, it's cramped as one area, and the corpus already holds entries SEC-G cannot express — panopticon's own 2.3.0 history: a panel that **confabulated an issue-filing it never performed**, and a panel that **copied a live DSN into its findings**. Provisional areas:

- `A prompt-injection-surfaces`: indirect-prompt-injection (HIGH — moves SEC-G1D), untrusted-content-in-agent-context (MEDIUM)
- `B tool-and-permission-scoping`: overbroad-tool-grant (MEDIUM), unscoped-write-authority (HIGH), missing-approval-gate-for-destructive-action (HIGH)
- `C output-trust-boundaries`: unstructured-llm-output-trusted-for-control (moves G1B), self-asserted-trust-metadata-spoofing (moves G1E), unauthenticated-external-data-rebuilds-trust (moves G1A)
- `D autonomy-and-oversight`: single-verifier-override-authority (moves G1C), **agent-confabulated-action** (HIGH, [corpus] 2.3.0), **secret-materialized-into-agent-output** (HIGH, [corpus] 2.3.0)
- `E resource-and-cost-safety`: unbounded-agent-loop (HIGH), unbounded-tool-call-budget (MEDIUM) **[invented]**
- `F data-egress`: sensitive-data-sent-to-model-provider (MEDIUM) **[invented]**

SEC keeps a cross-reference stub. SEC-G2 (fail-open) splits: the general fail-open pattern resolves with the existing ARC-F2/SEC-G2 big rock; only the agent-specific mediation gap (`G2C`) moves to AGT.

### Incubating domains — declare, don't seed (P2, content at 0.2+)

Add to the charter roadmap as **declared incubating**: **OPS** (production readiness: retry/backoff/circuit-breaker discipline, graceful shutdown, health checks, idempotent handlers, startup config validation), **A11Y** (WCAG crosswalk), **I18N** (hardcoded user-facing strings, locale-unaware formatting, translation-hostile string building). Each waits for a mining run on an appropriately-shaped repo — no codes burned on skeletons. The declaration itself is cheap (charter prose) and signals to first outside adopters that the taxonomy isn't backend-Python-only.
