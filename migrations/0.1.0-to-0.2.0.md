# OCRDb 0.2 — same-hazard cluster migration (Task 3, clean rewrite)

**Mechanism:** clean rewrite — every removed code's YAML block is **DELETED**
(no `status: deprecated`, no `superseded_by`, no tombstone). Distinct
`examples`/`cwe`/`recurrence` are folded into the named survivor before deletion.
Severity set by the **R2 bar** ("exploitable now, data loss, or silently wrong at
scale"). `see_also` pairs are only *recorded* here; they are populated in Task 5
(never point a `see_also` at a deleted code).

**Count:** 381 − 24 removals = **357** entries.
Per-domain: ARC 77→70 (−7), COD 58→55 (−3), QAL 58→51 (−7), SEC 73→70 (−3),
TST 80→76 (−4), AGT 16, DAT 19.

**Recurrence-fold policy:** two-entry double-home → survivor recurrence = max(X,Y)
(the sanctioned "take the higher" default), except cluster 14 where the audit note
says fold-in (sum). Multi-survivor clusters (11, 12, 16) where a removed entry's
observations split across two survivors → recurrence NOT mechanically folded
(avoids double-counting); noted for maintainer.

**CWE-fold policy:** fold a removed entry's CWE into the survivor when it fits the
survivor's hazard. CWE-1059 ("insufficient technical documentation") is folded into
documentation-category survivors (QAL area C) but **omitted** for correctness
survivors (COD area C) where it does not fit — each omission noted.
